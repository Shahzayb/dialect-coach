# Surface a rejected connection instead of "no speech"

## Problem

With file-backed audio, SDK 1.51.1 does not raise `canceled` when Azure refuses the WebSocket
upgrade (401 on a bad key or key/region mismatch). The continuous session fires only
`session_started` and `session_stopped`, so `_continuous_session` ends with no payloads and no
failure and raises `NoSpeechDetected` — telling the user to check their microphone when the
real fault is the credentials. Reproduced live on 2026-10-27; `recognize_once` on the same
file does return `Canceled` with the 401 detail.

## Change

- `_continuous_session` takes `wav_path` and watches `Connection.from_recognizer(...).connected`.
- If the session ends with no payloads, no failure, **and the connection never opened**, it runs
  one plain `recognize_once` on the same file. A `Canceled` result goes through
  `classify_cancellation`, so a 401 becomes the existing credentials `PermanentError`. Anything
  else falls through to `NoSpeechDetected` as before.
- The probe runs only when Azure never accepted the connection, so a genuinely silent clip on
  working credentials costs nothing extra.
- `classify_cancellation` also reads `code`, the attribute name `CancellationDetails` uses
  (events use `error_code`).

## Tests

`tests/test_cancellation.py`: the fake recognizer gains a fake `Connection`; a session that never
connects and whose probe is cancelled with `AuthenticationFailure` raises the credentials error;
a session that connected and heard nothing still raises `NoSpeechDetected` without probing.
